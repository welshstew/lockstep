See where your Vaults disagree. Bring them back in step.

Lockstep lines up two HashiCorp Vault KV v2 mounts, across clusters, environments or paths, and shows every secret and key that differs. Values are compared on the server and stay hidden until you ask. Copies go through a review and never overwrite a change you didn’t see.

Try the live demo View the source

Open source under the MIT licence. Runs in Kubernetes, in Docker, or as a command-line tool.

What it does

Find drift

Compare anything to anything
Two Vaults, two mounts or two path prefixes, down to a number that became a string.
Comparison profiles
Pair services/*/prod/** with services/*/staging/** and ignore keys that differ by design. Build the rules by clicking Ignore in the results.
Configuration, too
Secrets engines, auth methods, their tuning, roles and keys, compared across two Vaults.
Drift checks in CI
lockstep compare exits non-zero when environments drift, with no values in the log.

Change safely

Review, then write
Every copy, edit and delete is reviewed first and written with check-and-set, so a change made since you compared is never overwritten.
Plans for someone else
Save reviewed changes as a signed file, without values, for a colleague with write access to apply.
Browse and edit
A folder tree of one mount, versions with diffs and roll back, metadata, one-time sharing.
Export and import
Encrypted exports, and imports that turn dev into test on the way.

Understand what’s there

Who can do what
What a policy, or your own token, allows on every secret, in plain words. Build policies, try them for real, and write them after a review.
Certificates and keystores
PEM chains validated link by link, PKCS#12, JKS and JCEKS, opened with the password stored next to them.
Expiry at a glance
Every certificate in one or both mounts, including those in keystores and PKI engines, sorted by expiry.
Developer tools
Transit encryption, database credentials, leases, and development certificates from PKI.

Review before anything is written

Stage copies key by key. The review shows exactly what each target will get, its version change, and whether you’re allowed to write it. Then apply it yourself, or save it as a plan for someone else.

Promote a whole environment

Export production’s services/ with a one-time key, then import it into staging: paths /prod/ become /staging/, values ending -prod end -staging. The preview shows every secret and key before anything is written.

Guide: export, import and migrate secrets

Ignore the noise in a few clicks

Hostnames and per-environment passwords are meant to differ. Press Pick what to ignore, click Ignore on what doesn’t matter, check the result, and save it as a profile for the next comparison and for CI.

Guide: build a comparison profile

Know what each value is

Lockstep works out what’s inside each value: a PKCS#12 file, a Java keystore, a certificate chain, an image. It opens keystores with the password stored next to them, or finds it elsewhere in the folder, and checks every certificate.

From the terminal, too

lockstep compare writes a YAML report of what differs: no values, but a Vault UI link and a vault kv get command for every secret. Set an action on the keys to change and lockstep apply copies them, asking before each one.

$ lockstep compare --mount app-config -o report.yaml
  different   payments/db     differs: password
  left only   services/api
  right only  services/queue

12 secrets: 9 equal, 1 different, 1 left only, 1 right only.

$ lockstep apply report.yaml
staging · app-config/payments/db   from prod · app-config/payments/db
  1 key to write (v7 to v8):
    update password
  Write password? [y]es / [n]o / [a]ll / [q]uit: y
  Written: v8 (1 key).

Built to run in production

  • Stateless. Sessions live in an encrypted cookie, so any number of replicas can serve any request.
  • Sign in your way. Token, userpass, LDAP, OIDC, JWT from a CI job, or the pod’s Kubernetes service account, with login MFA.
  • Hardened images. Distroless and non-root on Red Hat Hardened Images, multi-arch, signed with cosign, with an SBOM and build provenance.
  • A tested Helm chart. Read-only filesystem, NetworkPolicy, PodDisruptionBudget, and a session key kept across upgrades, installed into a real cluster in CI.
  • Look-only when you want it. One setting refuses every write; others turn off exports, destroy or policy writes.
  • Audited. Every write is logged with who, where and a hash of what was there, never a value.

Install

Kubernetes (Helm)

helm upgrade --install lockstep \
  oci://ghcr.io/welshstew/charts/lockstep \
  -n lockstep --create-namespace \
  --set 'vaults[0].name=Production' \
  --set 'vaults[0].url=https://vault.example.com'

Try it locally

git clone https://github.com/welshstew/lockstep
cd lockstep
make up    # two demo Vaults + Lockstep
open http://localhost:8080

Command line

pipx install "git+https://github.com/welshstew/lockstep@v0.8.0#subdirectory=backend"
lockstep compare --help

# or run it from the image
docker run --rm -it --entrypoint lockstep ghcr.io/welshstew/lockstep:0.8.0 --help

Configuration, authentication, deployment and command-line guides are in the documentation.
